# 02 — The GitHub Actions build

Workflow: [`.github/workflows/build.yml`](../.github/workflows/build.yml).
No secrets or self-hosted runners are required: everything runs on
`ubuntu-24.04`.

## What the pipeline does

1. **Checkout** this repo.
2. **Free disk** — the runner starts with ~25 GB free; the image build needs
   a chroot (~2 GB) plus the rootfs image (~2 GB).
3. **Get pmbootstrap** from `https://gitlab.nura.eco/nura/pmbootstrap.git`
   and symlink `pmbootstrap.py` into `/usr/local/bin`.
4. **Get pmaports** (shallow clone of `main`, or the branch given in the
   manual-run input) and copy `pmaports/` from this repo over it. Our device
   and kernel packages therefore shadow nothing upstream, they simply appear
   as new `device/testing/*` packages.
5. **Write `~/.config/pmbootstrap_v3.cfg`** with `device`, `kernel`, `ui`,
   `work`, `aports`, `jobs`, `service_manager=openrc` and the mirror
   section. All prompt defaults are now answered, so:
6. **`pmbootstrap init`** runs non-interactively (`yes "" | …`); it validates
   the device/kernel selection and finishes setup.

   `init` also needs the pmaports clone to have a remote pointing at the
   canonical `gitlab.postmarketos.org` URL: it reads `channels.cfg` with
   `git show <remote>/main:channels.cfg`. Because our clone comes from the
   Nura mirror, the workflow adds that remote and points its
   `refs/remotes/postmarketos/main` at the commit we checked out.
7. **Prefetch the kernel source** into `$PMB_WORK/cache_distfiles` (mounted
   at `/var/cache/distfiles` inside the chroots). `codeload.github.com`
   answers `429 Too Many Requests` for anonymous archive downloads from
   shared runner IPs, so the step downloads with backoff and installs the
   file with `sudo` (pmbootstrap creates that directory root-owned).
8. **`pmbootstrap checksum`** recomputes `sha512sums` for both packages. It
   now finds the tarball already on disk, so it only verifies the hash — the
   committed hashes are a convenience, CI never trusts them.
9. **`pmbootstrap build linux-postmarketos-qcom-msm8953-c7`** compiles the
   kernel first, so a broken DTS fails early instead of at the end.
10. **`pmbootstrap install --split --password 147147`** builds the rootfs
    with OpenRC and the SSH daemon enabled (no display yet, so SSH over USB
    networking is the way in). `--split` produces a bare ext4 rootfs without
    a partition table, which is exactly what can be written to `USERDATA`.
11. **`pmbootstrap export --odin`** collects `boot.img`, the rootfs image, the
    Odin tar and the DTBs; they are copied to `out/` together with a
    `SHA256SUMS` file.
12. **Log** (`$PMB_WORK/log.txt`) is copied and the artifact is uploaded with
    `if: always()`, so failures are debuggable from the Actions page.

## Artifact layout

```
nura-c7-<run>/
├── boot.img                 Android boot image (kernel + initramfs + DTB)
├── samsung-c7lte-root.img   ext4 rootfs (USERDATA)
├── samsung-c7lte.tar.md5    boot.img packaged for Odin (optional path)
├── dtbs/qcom/…              generated DTBs, for inspection
├── build.log                pmbootstrap log
└── SHA256SUMS
```

## Timings and cost

| Step | Typical |
| --- | --- |
| pmbootstrap init + checksum | 1–2 min |
| Kernel build (qemu, LLVM) | 40–120 min |
| Rootfs install (console UI) | 10–20 min |
| Export + upload | 2–3 min |

Public repos get free runner minutes; private repos consume the account's
quota (roughly 60–150 minutes per run). The weekly `schedule` run exists to
detect upstream breakage — disable it if minutes are tight.

## Debugging a failed run

- Open the *Collect log* step and download `build.log` from the artifact;
  pmbootstrap prints the failing package and the last 100 lines.
- A red *Build the C7 kernel package* step almost always means a DTS syntax
  error. Reproduce locally by copying `dts/msm8953-samsung-c7lte.dts` into a
  mainline tree and running `make ARCH=arm64 LLVM=1 qcom/msm8953-samsung-c7lte.dtb`.
- A red *Build the image* step after a green kernel is usually a package
  dependency problem (`device-samsung-c7lte` depends list) or a missing
  `postmarketos-base` subpackage.

## Running the same build locally

On any x86_64 Linux box with Docker or a normal distro:

```sh
git clone --depth=1 https://gitlab.nura.eco/nura/pmbootstrap.git
sudo ln -sf "$PWD/pmbootstrap/pmbootstrap.py" /usr/local/bin/pmbootstrap
git clone --depth=1 https://gitlab.nura.eco/nura/pmaports.git /tmp/pmaports
cp -a pmaports/. /tmp/pmaports/
pmbootstrap -p /tmp/pmaports init
pmbootstrap -p /tmp/pmaports install --split --password 147147
pmbootstrap -p /tmp/pmaports export --odin
```

(On this repository's host machine — an Android/bionic device — pmbootstrap
cannot run; the CI path is the supported one.)
