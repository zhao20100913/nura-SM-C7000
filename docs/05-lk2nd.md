# lk2nd for the C7 (SM-C7000)

lk2nd is the little secondary bootloader that gets loaded by Samsung's ABL
straight from the `BOOT` partition. It gives the C7 a standard Android fastboot
interface, which is what makes `fastboot flash boot boot.img` possible at all on
a Samsung device.

This repo builds it for you:

- `lk2nd/msm8953-samsung-c7lte.dts` — the C7 device tree
- `.github/workflows/lk2nd.yml` — Actions job that clones
  [msm8916-mainline/lk2nd](https://github.com/msm8916-mainline/lk2nd), adds the
  C7 dtb to the msm8953 platform, and uploads `lk2nd.img`

## Why the current image says “Unknown (FIXME!)”

The menu line under the version is `lk2nd_dev.model`. It is filled in from the
device node that lk2nd matches against `androidboot.bootloader`; when nothing
matches, lk2nd has no model and prints `Unknown (FIXME!)`.

The current lk2nd tree looks for that device node at a **fixed path**:

```c
lk2nd_node = fdt_path_offset(dtb, "/lk2nd");   /* lk2nd/device/device.c */
```

and every supported device is a subnode of it:

```dts
&lk2nd {
        c7lte {
                model = "Samsung Galaxy C7 (SM-C7000)";
                compatible = "samsung,c7lte";
                lk2nd,match-bootloader = "C7000*";
        };
};
```

The dtb that is currently flashed was written for the **old** (msm8953-mainline
fork) layout, where the device node sits directly under `/`:

```dts
/ {
        qcom,msm-id = <293 0>;
        qcom,board-id = <8 3>;
        c7lte-generic {                      /* <-- too high up  */
                model = "Samsung Galaxy C7 (SM-C7000)";
                lk2nd,match-bootloader = "C7000*";
        };
};
```

ABL happily loads it (the QCDT ids are right), so lk2nd boots and the menu
works — but `find_device_node()` returns `-FDT_ERR_NOTFOUND`, the model stays
NULL and you get `Unknown (FIXME!)`. The same reason explains why no panel is
listed: `lk2nd_dev.panel` is never parsed from a matching node.

You can confirm this on a running device without reflashing:

```sh
fastboot oem dtb          # dumps the dtb lk2nd was started with
fastboot get_staged dtb.bin
dtc -I dtb -O dts dtb.bin | grep -A5 lk2nd
```

(If `dtc` is not installed, `grep -a` for `lk2nd,device` in the dump works too.)

## Build

The workflow `Build lk2nd (SM-C7000)` does exactly this, but locally:

```sh
# Debian/Ubuntu dependencies
sudo apt install gcc-arm-none-eabi device-tree-compiler libfdt-dev python3 build-essential

git clone --depth=1 https://github.com/msm8916-mainline/lk2nd.git
cp lk2nd/msm8953-samsung-c7lte.dts lk2nd/lk2nd/device/dts/msm8953/

# add msm8953-samsung-c7lte.dtb to both ADTBS and QCDTBS in
# lk2nd/lk2nd/device/dts/msm8953/rules.mk

cd lk2nd
make -j"$(nproc)" TOOLCHAIN_PREFIX=arm-none-eabi- lk2nd-msm8953
# -> build-lk2nd-msm8953/lk2nd.img
```

The QCDT (device id table) is generated by `lk2nd/scripts/dtbTool` from
`QCDTBS`, which is why the dtb must be added to **both** lists: `ADTBS` appends
it to the image, `QCDTBS` produces the table that ABL matches
`qcom,msm-id` / `qcom,board-id` against.

`qcom,board-id` is declared as `<8 3>, <8 4>` in our dtb: the C7 that was
tested reports `8 3`, the downstream Samsung DTS uses `8 4`, and ABL revisions
differ. Having both pairs means either loader finds a dtb.

## Flash

```sh
# one time: lk2nd goes into BOOT
heimdall flash --BOOT lk2nd.img --no-reboot

# afterwards, from lk2nd's fastboot:
fastboot flash boot boot.img          # written at a 512 KiB offset
fastboot flash userdata samsung-c7lte-root.img
```

`fastboot flash boot` writes to `BOOT+512 KiB`, so lk2nd itself survives and you
can keep iterating without Heimdall. `fastboot oem log` / `fastboot get_staged`
pull lk2nd's log if something goes wrong.

## What is still missing in this dtb

- **Panel**: the C7 has a Samsung S6E3FA3 (AMS568HN31) 1080x1920 command-mode
  panel (TE GPIO 24, reset GPIO 50, enable GPIO 94). lk2nd can only *match* a
  panel if ABL passes `mdss_mdp.panel=...`; add a `panel { ... }` node with the
  exact stock panel name once it is known (see the TODO block in the dts).
- **Touch**: Melfas MMS449 on `i2c_7` (IRQ GPIO 59, `vdd_en` GPIO 95) — only
  needed if touch has to work inside lk2nd (it does not).
- **MUIC reset**: if USB does not enumerate in lk2nd, add a
  `samsung,muic-reset` node (SM5705). Not needed while fastboot over the
  bootloader's own USB works.

These do not block booting a mainline kernel: they are only used by lk2nd for
hardware detection and for passing a panel name to downstream kernels.

The workflow has produced a working image:

- run: <https://github.com/zhao20100913/nura-SM-C7000/actions/runs/43101091696>
  (green; ~40 s of actual work once a runner is assigned)
- artifact: `lk2nd-c7-6`
- `lk2nd.img`: 374,800 bytes, sha256
  `8ff0f8d6c641d4c7ab16f9b55b48148c595f3c066326356c246e4ef13be3711b`
- the embedded dtb decompiles to `model = "Samsung Galaxy C7 (SM-C7000)"`,
  `qcom,msm-id = <0x125 0>`, `qcom,board-id = <0x08 0x03 0x08 0x04>` and
  `lk2nd,match-bootloader = "C7000*"`, so lk2nd should stop printing
  `Unknown (FIXME!)` once this image is flashed.

Two CI workarounds are worth knowing about, because the obvious approach does
not work on the hosted runners:

- `device-tree-compiler` is **not** installed through apt: every run failed to
  resolve `azure.archive.ubuntu.com`. The two Ubuntu 24.04 `.deb`s
  (`libfdt1_1.7.0-2build1`, `device-tree-compiler_1.7.0-2build1`) are fetched
  from `mirrors.edge.kernel.org` and installed with `dpkg -i` instead.
- the ARM toolchain comes from `carlosperate/arm-none-eabi-gcc-action`
  (release `15.3.Rel1`), exactly like upstream lk2nd CI, instead of the
  `gcc-arm-none-eabi` apt package.
